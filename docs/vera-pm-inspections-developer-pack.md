# Inspections & Checklists — Developer-Ready Pack

PM field inspections module: versioned templates, checklist execution, auto-deficiencies, CAPA/CAIL, equipment lockout, SIF ingestion, offline sync.

**API base:** `/api/v1/pm/inspections`  
**UI:** `/pm/inspections`  
**Offline sync:** `pmInspections.sync`  
**Legacy VSI walk-arounds:** `/pm/safety-intelligence/inspections` (`SafetyInspection` tables — separate from PM module)

---

## 2. Database schema

### `pm_inspection` (spec: `inspections`)

| Field | Type | Spec alias |
|-------|------|------------|
| id | UUID PK | id |
| projectId | Int | project_id |
| inspectorUserId | Int | inspector_id |
| templateId | String FK | template_id |
| templateVersion | Int | version at create |
| status | `PmInspectionStatus` | draft, in_progress, submitted, review_required, approved, rejected, closed |
| riskScore | Int? | risk_score |
| scorePercent | Float? | pass % |
| passed | Boolean? | overall pass |
| answers | Json | **replaces normalized `inspection_items`** — keyed by checklist item id |
| equipmentId, workerId, siteId | Int? | subject context |
| requiresSupervisorReview | Boolean | |
| clientSyncId | String? unique | offline |
| deletedAt | DateTime? | soft delete |
| createdAt, updatedAt | DateTime | timestamps |

**Indexes:** `(projectId, status)`, `(inspectorUserId, createdAt)`, `(equipmentId, status)`

### Checklist items (spec: `inspection_items`)

Stored in **`pm_inspection_template.items`** JSON array:

```json
{
  "id": "item-1",
  "label": "Guard in place",
  "type": "pass_fail",
  "required": true,
  "weight": 1,
  "failValues": ["fail", "no"],
  "showIf": { "itemId": "parent", "equals": "yes" },
  "energyType": "gravity"
}
```

Answers on inspection: `{ "item-1": "pass", "item-1_notes": "OK" }`  
Status per item derived: pass / fail / na from answer value vs `failValues`.

## 3. API contract

Base: `/api/v1/pm/inspections` — JWT + PM roles (WORKER+ read; SUPERVISOR+ templates/publish/review).

### Templates

| Method | Path | Description |
|--------|------|-------------|
| GET | `/templates?companyId=&projectId=&status=` | List templates |
| GET | `/templates/:id` | Template detail |
| POST | `/templates` | Create (supervisor+) |
| PUT | `/templates/:id` | Update draft |
| POST | `/templates/:id/publish` | Publish workflow |
| POST | `/templates/:id/version` | New version fork |
| POST | `/templates/seed?companyId=` | Default PME/crane/site templates |

### Inspections (spec paths)

| Method | Path | Body | Description |
|--------|------|------|-------------|
| GET | `/` | query filters | List inspections |
| POST | `/` | templateId, companyId, projectId, … | **Create inspection** (spec `POST /inspection`) |
| GET | `/:id` | | Full inspection + deficiencies |
| PUT | `/:id/answers` | `{ answers: {} }` | Save checklist answers → `in_progress` |
| POST | `/:id/items` | `{ answers }` or `{ items }` | **Alias** for save answers |
| POST | `/:id/submit` | | Score, deficiencies, CAPA, equipment lockout |
| POST | `/:id/review` | action, notes | approve \| reject \| request_changes |
| POST | `/:id/deficiencies` | itemId, title, severity, … | **Manual deficiency** |
| POST | `/:id/signatures` | role, signatureData | |
| POST | `/:id/attachments` | file metadata | |

### Deficiencies

| Method | Path | Description |
|--------|------|-------------|
| POST | `/deficiencies/:deficiencyId/verify` | Close deficiency (supervisor+) |

### CAIL / predict

| Method | Path | Description |
|--------|------|-------------|
| POST | `/predict` | Dry-run: `{ templateId, answers }` → predicted deficiencies before submit |
| GET | `/intelligence/project/:projectId` | Quality score, hazard patterns |
| GET | `/intelligence/inspector/:userId?projectId=` | Inspector performance |
| GET | `/analytics/project/:projectId` | Compliance metrics |

### Offline & access

| Method | Path |
|--------|------|
| POST | `/sync` | Idempotent offline upload + optional submit |
| GET | `/access/worker?workerId=&projectId=` | Block if critical deficiencies / overdue equipment inspection |

## 5. Workflow logic

### States (`PmInspectionStatus`)

```
draft ──save answers──► in_progress ──submit──► submitted
                              └──────────────► review_required (failed / high risk / high energy)
submitted | review_required ──approve──► approved (closedAt set)
                            ──reject──► rejected
                            ──request_changes──► in_progress
```

### Deficiency states (`PmDeficiencyStatus`)

```
open ──assign──► assigned ──work──► in_progress ──verify──► closed
```

### Transitions & validations

| Step | Validation | Permission |
|------|------------|------------|
| Create | Template must be `published` | Worker+ |
| Save answers | Required visible items answered | Worker+ |
| Submit | Required signatures present; scoring runs | Worker+ |
| Auto deficiencies | Created for each failed checklist item | System |
| Review approve | Status in submitted/review_required | Supervisor+ |
| Verify deficiency | Supervisor+ | |

### Submit side effects

1. Score inspection (`scorePercent`, `riskScore`, `passed`)
2. Create deficiencies for failed items
3. Emit CAIL or create unified CAPA (`fromInspectionDeficiency`)
4. Ingest deficiency to SIF (`ingestDeficiencyToSif`)
5. Equipment lockout if critical severity

## 6. CAIL intelligence logic

### `PmInspectionsCailIntelligenceService`

| Capability | Method | Logic |
|------------|--------|-------|
| Predictive deficiency detection | `predictFromAnswers` | Run scoring engine without DB write; list failed items + severities |
| Inspection quality scoring | `projectInsights` | `100 - avgRisk - failed*5` |
| Weak control detection | Failed items with `energyType` | Flag high-energy pattern |
| Hazard patterns | Open deficiencies grouped by category | Repeat ≥3 → "Elevated repeat deficiency" |

### Explainability (project insights)

```text
inspectionQualityScore = max(0, 100 - averageRiskScore - failedCount * 5)
```

### Inspector performance

```text
passRate = passed inspections / total
reviewEscalationRate = requiresSupervisorReview / total
inspectorScore = passRate * 80 + min(20, total * 2)
```

## 7. Offline mode

### Local data

- Templates: `GET /templates?status=published` cached before field work
- Inspection: created with `clientSyncId` (UUID)
- Answers + signatures bundled in sync payload

### Sync (`POST /sync`)

```json
{
  "clientSyncId": "uuid",
  "templateId": "...",
  "companyId": 1,
  "projectId": 1,
  "answers": { "item-1": "pass" },
  "signatures": [{ "role": "inspector", "signatureData": "..." }],
  "submitted": true
}
```

Handler: `pmInspections.sync` in `vera-frontend/lib/field/sync-handlers.ts`

### Conflict resolution

- Same `clientSyncId` → return existing row; re-submit if still draft

## 9. Analytics

**GET `/analytics/project/:projectId`**

| Metric | Description |
|--------|-------------|
| totalInspections | Count all inspections |
| failedInspections | `passed === false` |
| openDeficiencies | Not closed |
| deficiencyBySeverity | groupBy severity |
| inspectionsByTemplate | groupBy templateId |
| passRate | % inspections passed |
| complianceScore | Same as pass rate (leading indicator) |
| trends.inspections90d | Inspections in last 90 days |
| trends.deficienciesClosed90d | Closed deficiencies in 90d |
| trends.deficiencyRate90d | Open vs closed ratio |
| inspectorCount | Distinct inspectors |

### Leading indicators

- Pass rate / compliance score
- Open deficiency count
- CAIL `inspectionQualityScore` (from `/intelligence/project/:id`)

### Lagging indicators

- Failed inspection count
- Deficiencies closed (90d)
- Inspector review escalation rate

### Deficiency trends

- `deficiencyBySeverity` distribution
- `hazardPatterns` from CAIL (repeat categories)
